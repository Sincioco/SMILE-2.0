Safe Challenges After the Tutorial

Change one idea at a time, predict what will happen, test it, and keep notes.

ExperimentPredictTestObserve

  • Change the background Rgb.
  • Make the food orange.
  • Give the title a new named color.

  • Make food worth 20 points.
  • Begin with 7 segments.
  • Change StartDelay to 130.

Level 3: Design

  • Draw the head a different color.
  • Add a Length number to the side panel.
  • Add a border inside each segment.

The scientific change loop

  1. Question: What do I want to change?
  2. Prediction: Which variable, formula, or drawing command owns it?
  3. Small edit: Change one thing.
  4. Test: Try the exact behavior.
  5. Observe: Did reality match the prediction?
  6. Keep or undo: Save good experiments; restore bad ones.

Do not change five things at once

When many values change and the game breaks, you do not know which edit caused the problem. Small experiments create clear evidence.

Invent a feature: bonus food

Design a blue bonus food worth 50 points. Before writing code, answer these questions:

Data

What new X, Y, active flag, and timer might the feature need?

Rules

How does it spawn? When does it disappear? How does collision recognize it?

Drawing

Which color, size, and shape tells the player that it is special?

Testing

How will you prove it never appears under the snake and awards exactly 50 points?

Planning the model

Before a picture can appear, the program needs data that describes it. Before a rule can run, the program needs facts it can test. This is how programmers design features methodically.
