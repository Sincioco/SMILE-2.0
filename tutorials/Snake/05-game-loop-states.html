The heartbeat of a game

Game Loop & Named States

A game is information changing and being drawn again and again. A GameState Enum names the current screen instead of asking readers to remember magic numbers.

InputUpdateRulesDrawingState

One repeating game cycle

StageSnake asksExample
InputDid the player press a key?Get Key Key
UpdateIs it time to move?Timer() >= NextMoveTime
CheckWall, body, or food?Collision and food tests
DrawWhat do the current values look like?Call DrawBoard()
PresentCan the player see the finished frame?Show Screen

State chooses the current screen

SnakeModel.smile — no magic state numbers
Enum GameState
    Title
    Playing
    GameOver
End Enum

GameState.Title

Draw the title. Enter starts. Escape exits.

GameState.Playing

Translate input, move on schedule, check rules, and draw gameplay.

GameState.GameOver

Keep the board visible, draw the result panel, and allow retry.

Separate movement speed from frame speed

The window can read input and redraw many times while the snake moves only once every 45–100 milliseconds. This keeps the game responsive without making the snake impossibly fast.

Repetition builds memory

Reinforce what you learned

Say it again

Every frame follows the same idea: input → update → check → draw → show. State chooses which screen rules apply.

Recall it

Which state means the player is actively playing?
