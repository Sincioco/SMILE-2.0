Grid & Coordinates

The game thinks in board squares first. Drawing code later converts those squares into pixels.

X and Y0-based coordinates20-pixel cells

Model the world as a grid

The program does not need to say that the head is at pixel 362. It can say, “The head is in column 17, row 12.” Grid coordinates are easier to move and easier to test.

X answers “how far across?”

X = 0 is the leftmost column. Moving right adds 1. Moving left subtracts 1.

Y answers “how far down?”

Y = 0 is the top row. Moving down adds 1. Moving up subtracts 1.

Grid size and valid values

DimensionCountValid coordinatesWhy
Columns350 through 34Counting begins at zero, so the final valid index is 35 − 1.
Rows240 through 23The first invalid row is 24.
Cells84035 × 24The arrays reserve enough room for a snake that fills the entire board.

The conversion formula

For a snake segment, the upper-left drawing position is:

Grid-to-pixel formulas
PixelX = FieldX + GridX * CellSize + 2
PixelY = FieldY + GridY * CellSize + 2

See the same formula in the finished game

The real drawing routine uses the grid-to-pixel calculation directly. These are full source lines 242–243.

DrawBoard — actual Snake source
            Fill Rectangle FieldX + SnakeX[I] * CellSize + 2, FieldY + SnakeY[I] * CellSize + 2, 16, 16, Rgb(60, 230, 75)
            Draw Rectangle FieldX + SnakeX[I] * CellSize + 2, FieldY + SnakeY[I] * CellSize + 2, 16, 16, Rgb(20, 105, 35)
ValueCalculationResult
Head X = 1720 + 17 × 20 + 2362 pixels
Head Y = 1230 + 12 × 20 + 2272 pixels
Why does the final formula add 2?

The segment is drawn as a 16 × 16 square inside a 20 × 20 cell. A 2-pixel margin on each side makes separate body blocks visible.

Repetition builds memory

Reinforce what you learned

Say it again

X grows to the right, Y grows downward, and drawing converts grid squares into pixels.

Recall it

What happens to Y when the snake moves upward?

Check your answer

Y decreases by 1. You will use that rule again in MoveSnake, full source lines 182–190.
