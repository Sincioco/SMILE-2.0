1. BASIC LANGUAGE RULES

  • SMILE is case-insensitive. Print, PRINT, and print mean the same thing.
  • SMILE is line-oriented. A statement normally occupies one physical line; balanced parentheses allow multiline expressions, calls, and routine declarations.
  • Identifiers may contain letters, digits, and underscores, but cannot begin with a digit.
  • Number values are signed 64-bit integers.
  • Boolean values are True and False.
  • Text literals use double quotation marks. Type a quotation mark twice to include it inside the text.

Choose the right reusable construct:

  • Module — shared stateless services or singleton-style bounded storage, imported through an alias.
  • Type — a nominal value with recursive defaults and deep-copy assignment.
  • Class — a nominal reference object with identity, aliasing, constructors, and automatic reference counting.

Example:

PlayerScore = 100
IsAlive = True
Print "She said, ""Hello!"""

2A. OPTION EXPLICIT AND BUILT-IN TYPES

OPTION EXPLICIT disables implicit variables for one physical source file. In an application or support source, it must be the first non-comment statement. Inside a module, it follows MODULE and precedes imports and declarations.

Built-in types:

  • Number — signed 64-bit integer; default value 0.
  • Boolean — True or False; default value False.
  • Text — mutable UTF-8 text; default value "".
  • Image — a loaded image resource; default value is unloaded.

User-defined Enum, Type, and Class declarations add nominal types. Enums default to numeric value zero, Types default every field recursively, and Class references default to Nothing.

Syntax and example:

OPTION EXPLICIT

DIM Score AS NUMBER
DIM IsAlive AS BOOLEAN
DIM Caption AS TEXT
DIM Names[10] AS TEXT

Score = 100
IsAlive = TRUE
Caption = "Ready, " + Names[0]

Typed declarations require exact types; SMILE does not implicitly convert among Number, Boolean, Text, enums, Types, or Classes. Text supports + concatenation and ordinal =/<> comparison.

2B. MODULES, IMPORTS, AND VISIBILITY

A module groups reusable declarations. Declarations are private by default; prefix one with PUBLIC to export it, or PRIVATE to state private intent explicitly. Imports belong only to the physical source file that declares them.

Module source:

MODULE Example.Math

PUBLIC CONST Maximum = 100

PUBLIC FUNCTION Double(Value AS NUMBER) AS NUMBER
    RETURN Value * 2
END FUNCTION

END MODULE

Consumer source:

IMPORT Example.Math AS Math

PRINT Math.Double(21)
PRINT Math.Maximum

Qualified access uses Alias.Member. Public constants, arrays, subroutines, functions, enums, value Types, and reference Classes may be imported. Library-project sources must declare a module; an application may also contain local module sources.

2C. RECORD TYPES

TYPE Name ... END TYPE declares a nominal value type. Fields may use a built-in type, another visible record type, or an imported public record type. Fields cannot be arrays and cannot have initializers.

Syntax and example:

TYPE Point2D
    X AS NUMBER
    Y AS NUMBER
END TYPE

TYPE Actor
    Name AS TEXT
    Position AS Point2D
    Active AS BOOLEAN
END TYPE

DIM Hero AS Actor
DIM Party[4] AS Actor
Hero.Name = "Alyssa"
Hero.Position.X = 20
Party[0] = Hero
PRINT Party[0].Position.X

Records default every field recursively and use deep value-copy assignment. Separately declared types remain different even when their fields look identical. Records may be passed BYVAL or BYREF and returned from functions.

2D. Enum Types

Enum Name ... End Enum declares a closed nominal value type. Implicit numbering begins at zero and increments by one. Explicit values are signed 64-bit compile-time Number expressions, and later implicit values continue from the explicit value.

Syntax and example:

Public Enum CardinalDirection
    None = 0
    Up = 1
    Right = 2
    Down = 3
    Left = 4
End Enum

Dim Facing As CardinalDirection
Dim History[4] As CardinalDirection

Facing = CardinalDirection.Up
History[0] = Facing

Select Case Facing
    Case CardinalDirection.Up
        Print "Up"
    Case CardinalDirection.Down
        Print "Down"
End Select
  • Enum identity is exact: two declarations are never interchangeable, even if their members and values match.
  • There is no implicit conversion between an enum and Number, or between different enum types.
  • The supported operators are = and <> between values of the same enum type.
  • Duplicate numeric values are legal aliases, but duplicate-valued Select Case branches are diagnosed.
  • Imported members use Alias.EnumName.Member.
  • Enums may be scalars, array elements, fields, parameters, returns, property types, and optional defaults.

2E. Optional and Named Arguments

An optional parameter uses Optional Name As Type = Default. Required parameters come first. Optional parameters are ByVal and support Number, Boolean, Text, or an enum type.

Declaration and calls:

Sub Present(
    Value As Number,
    Optional Caption As Text = "Ready",
    Optional Enabled As Boolean = True
)

    Print Caption
    Print Value

End Sub

Call Present(3)
Call Present(Value:=4, Caption:="Named")
Call Present(5, Enabled:=False)
  • Named arguments use the single Visual Basic-style spelling Name:=Expression, with no spaces around :=.
  • Positional arguments must precede named arguments; named arguments may be reordered.
  • Each parameter may be supplied only once, and every required parameter must be supplied.
  • Defaults are compile-time literals, constants, or exact-type enum members.
  • Optional Type, Class, and Image defaults are not supported.
  • Explicit arguments are evaluated exactly once in source order, then mapped into declaration order.
  • Named arguments are not available for compiler-special built-in functions.

2F. Multiline Routine Declarations

Balanced declaration parentheses allow a Sub or Function parameter list to continue across physical lines. The opening ( remains on the declaration line; the continuation ends at the matching ).

Canonical form:

Public Function AddItem(
    Label As Text,
    UserValue As Number,
    Optional Enabled As Boolean = True
) As Number

    Dim Result As Number

    Result = UserValue

    Return Result

End Function
  • Generated and maintained code places one parameter per line, indented four spaces.
  • Every multiline parameter except the last ends with a comma.
  • The closing ) aligns with the declaration; a Function's As ReturnType stays on that same line.
  • Newlines remain significant outside balanced expression or declaration parentheses.
  • Square brackets do not create a general continuation context.

2G. With Blocks

With Target ... End With shortens repeated member access. The target is evaluated exactly once on entry, and a leading dot binds to the innermost active target.

Nested example:

With SkinWindow
    .UseSkin = True
    .BorderThickness = 2

    With .Padding
        .Left = 34
        .Top = 28
        .Right = 28
        .Bottom = 26
    End With
End With
  • A Type target must be a stable writable location: variable, parameter, array element, field, or leading-dot field.
  • A Class target captures and retains one object identity for the whole block, even if the source variable is rebound.
  • Nested blocks are legal; each leading dot uses the innermost target.
  • Methods and properties may be called through the leading-dot form.
  • A leading dot outside With is diagnosed.
  • Temporary Type results are not supported as targets.

2H. Type Methods and Properties

A Type remains a nominal deep-copy value but may contain instance Subs, Functions, and Properties. Its hidden writable receiver is named Me. Fields are Public; methods and properties default Public and may be Private.

Value-Type behavior:

Type Counter

    Label As Text
    StoredValue As Number

    Public Sub Advance(
        Optional Delta As Number = 1
    )

        Me.StoredValue = Me.StoredValue + Delta

    End Sub

    Public Property Total As Number

        Get

            Dim ReturnValue As Number

            ReturnValue = Me.StoredValue

            Return ReturnValue

        End Get

        Set

            Me.StoredValue = Value

        End Set

    End Property

End Type

Dim First As Counter
Dim Copy As Counter

Call First.Advance(Delta:=2)
First.Total = 9
Copy = First
Call Copy.Advance()

Print First.Total
Print Copy.Total

Copy = First makes an independent deep copy. A mutating Type member requires an addressable receiver; variables, parameters, array elements, nested writable fields, and active With targets qualify. A Function or Property result is not a writable Type receiver.

A Property contains Get, Set, or both. Value is a contextual implicit setter parameter and is not globally reserved. Quick Info and hover never execute a getter.

2I. Class References

A Class is a nominal reference object with identity. Class assignment and ByVal arguments retain the same object; ByRef may rebind the caller's reference. Class fields default Private, while methods and Properties default Public.

Construction, properties, and identity:

Class Counter

    Private StoredValue As Number

    Public Sub New(
        Optional Start As Number = 0
    )

        Me.StoredValue = Start

    End Sub

    Public Sub Advance(
        Optional Delta As Number = 1
    )

        Me.StoredValue = Me.StoredValue + Delta

    End Sub

    Public Property Total As Number

        Get

            Dim ReturnValue As Number

            ReturnValue = Me.StoredValue

            Return ReturnValue

        End Get

    End Property

End Class

Dim First As New Counter(Start:=10)
Dim Alias As Counter

Alias = First
Call Alias.Advance()

Print Alias Is First

Alias = Nothing
Print Alias Is Nothing
Print First Is Not Nothing
  • A Class supports zero or one Public Sub New. Without one, SMILE supplies an implicit parameterless constructor.
  • New ClassName(...) creates an object; Dim Name As New ClassName(...) declares and initializes a scalar reference.
  • Uninitialized Class variables contain Nothing.
  • Is and Is Not test identity. = and <> are not Class identity operators.
  • Member access on Nothing fails deterministically.
  • Supported fields are Number, Boolean, Text, Enum, Type, and fixed one/two-dimensional arrays of those non-Class values.
  • Class-reference fields, Class arrays, direct Image fields, inheritance, interfaces, generics, overloads, events, user finalizers, and tracing garbage collection are intentionally deferred.

Native and Web use deterministic automatic reference counting. Final release clears owned Text, contained Type data, and fixed arrays before freeing the object. End Program, scope exits, overwritten references, returns, and failed calls release owned references.

12. SUB PROCEDURES

Syntax:

SUB Name
    Statements
END SUB

SUB Name([BYVAL | BYREF] Parameter1 [AS Type], Parameter2 [AS Type])
    Statements
END SUB

CALL Name()
CALL Name(Argument1, Argument2)

Example:

SUB AddScore(BYREF Score AS NUMBER, Points AS NUMBER)
    Score = Score + Points
END SUB

CALL AddScore(Score, 100)

Missing mode means BYVAL. Missing type preserves the legacy numeric calling convention. BYREF requires an exact-type writable variable, array element, parameter, record, or record field. Current native and Web calls have no four-parameter language restriction; tested signatures include up to 16 parameters. RETURN without a value may be used to leave a SUB early.

Example:

SUB DrawPlayer(X, Y)
    IF X < 0 THEN
        RETURN
    END IF
    FILL CIRCLE X, Y, 12, CYAN
END SUB

13. FUNCTIONS

FUNCTION Name
    Statements
    RETURN Expression
END FUNCTION

FUNCTION Name([BYVAL | BYREF] Parameter1 [AS Type], Parameter2 [AS Type]) [AS ReturnType]
    Statements
    RETURN Expression
END FUNCTION

Example:

FUNCTION PointsFor(Row AS NUMBER) AS NUMBER

15A. Multiline Parenthesized Expressions

SMILE remains line-oriented, but a balanced pair of expression parentheses explicitly allows physical newlines. This supports readable long conditions, assignments, nested calls, ordinary calls, qualified calls, and Call statements.

Preferred trailing-operator condition:

If (Style.CursorWidth < 0 Or
    Style.CursorWidth > Core.UI_MAX_LAYOUT_VALUE Or
    Style.CursorHeight < 0 Or
    Style.CursorHeight > Core.UI_MAX_LAYOUT_VALUE) Then
    Return False
End If

Multiline call:

Call Menu.UpdateItem(
    MenuHandle,
    ItemIndex,
    Result
)
  • Keep If ... Then on one line when it is at most 100 characters and has no more than two top-level Boolean clauses.
  • Otherwise, parenthesize the complete condition and place one continued clause on each indented line.
  • Use the preferred trailing And/Or layout shown above.
  • Newlines outside balanced expression or declaration parentheses still end the statement.
  • Square brackets do not create a general continuation context.

16. BUILT-IN FUNCTIONS

TIMER()

Returns elapsed time in milliseconds.
Example: StartTime = TIMER()

RGB(Red, Green, Blue)

Creates a color from red, green, and blue components.
Example: SkyColor = RGB(40, 120, 220)

ABS(Value)

Returns the absolute value.
Example: Distance = ABS(PlayerX - EnemyX)

MIN(First, Second)

Returns the smaller value.
Example: Health = MIN(Health, 100)

MAX(First, Second)

Returns the larger value.
Example: Score = MAX(Score, 0)

GAME_CLOSED()

Returns TRUE when the game window has been closed.
Example: LOOP UNTIL GAME_CLOSED() = TRUE

KEY_HELD(KeyCode)

Returns TRUE while a named key is held down.
Example: IF KEY_HELD(KEY_LEFT) = TRUE THEN

Image functions:

Image_Width(Portrait)
Image_Height(Portrait)
Image_Loaded(Portrait)

Text measurement and Unicode functions:

Text_Width(Caption, 28)
Text_Height(Caption, 28)

Text_Code_At returns -1 for an invalid index. Text_Slice clamps safely and returns empty text for a negative start, nonpositive count, or a start beyond the end.

19A. GAME-CANVAS POINTER INPUT

Every Game Window program can read mouse, pen, and touch contacts through one cross-target logical-canvas API. Native input is mapped through letterboxing; Web input is mapped through CSS size and device-pixel scaling.

Position, movement, and wheel:

Pointer_X()
Pointer_Y()
Pointer_Delta_X()
Pointer_Delta_Y()
Pointer_Wheel_Delta()
Pointer_Inside()

Button state:

Pointer_Held(Button)
Pointer_Pressed(Button)
Pointer_Released(Button)

Drag example:

If Pointer_Pressed(POINTER_PRIMARY) Then
    Dragging = True
End If

If Dragging And Pointer_Held(POINTER_PRIMARY) Then
    ObjectX = ObjectX + Pointer_Delta_X()
    ObjectY = ObjectY + Pointer_Delta_Y()
End If

If Pointer_Released(POINTER_PRIMARY) Then
    Dragging = False
End If
  • Pointer_X() and Pointer_Y() return logical Game Window coordinates.
  • Pointer_Inside() reports whether the latest position lies inside the logical canvas.
  • Deltas, wheel movement, and pressed/released transitions accumulate during the current frame.
  • Show Screen ends the input frame and clears accumulated deltas and transitions; held state and the last position remain.
  • Capture loss, cancellation, focus loss, page hiding, runtime completion, and failure release active contacts to prevent stuck input.

20A. WEB VIRTUAL CONTROLS

Generated Web games include a dependency-free, touch-first controller overlay. It feeds the same bounded Get Key queue and Key_Held(...) state as a physical keyboard; it is host UI rather than SMILE drawing or new statement syntax.

Standard mapping:

  • D-pad: KEY_UP, KEY_DOWN, KEY_LEFT, and KEY_RIGHT.
  • Action buttons: KEY_PAD_A, KEY_PAD_B, KEY_PAD_X, and KEY_PAD_Y.
  • The standard pad intentionally does not emit KEY_ESCAPE, because some games use Escape for immediate termination.

Visibility override:

?smile-controls=auto
?smile-controls=on
?smile-controls=off

auto is the default and uses input capabilities—not the browser user agent. Controls stay hidden until Game Window is created. Portrait and landscape layouts respond dynamically, honor safe areas, use accessible real buttons, and support simultaneous direction-plus-action contacts.

The standard profile is designed for ordinary single-player controls. It does not infer custom mappings or same-device multiplayer layouts.

A SMILE library project uses the .smilelibproj extension and builds a deterministic, target-neutral format-6 .smilelib package. The same package can be consumed by Windows and Web applications.

Module MyGame.Math

Option Explicit

Public Const MAXIMUM_SCORE = 999999

Public Function Clamp(Value As Number, Minimum As Number, Maximum As Number) As Number

    Dim ReturnValue As Number

    ReturnValue = Max(Minimum, Min(Value, Maximum))

37K. Coding Formatting and Conventions

These are the repository's current authoritative authoring conventions, versioned August 17, 2026. They apply to programs, modules, libraries, examples, templates, tutorials, and generated SMILE. They do not make the case-insensitive language case-sensitive.

Capitalization and names:

  • Write keywords with Visual Basic-style initial capitalization: Dim, As, If, Then, End If, Sub, Function, With, Enum, Type, Class, Property, Get, Set, Me, New, Nothing, Is Not, Optional, and Game Window.
  • Use PascalCase for ordinary variables, parameters, routines, modules, types, classes, properties, enum members, and fields; never write them in all uppercase.
  • Reserve uppercase for constants and established acronyms: KEY_ENTER, WHITE, MAX_ITEMS, SMILE, UI, VSIX, API, IDE.
  • Use title/initial capitalization for short UI labels and normal English sentence capitalization for complete sentences.

Whitespace:

  • Indent every block and continuation level with exactly four spaces; never use tabs.
  • Use exactly one blank line at a required separation point; never use double or triple blank lines.
  • Follow the last consecutive Const, Module, Import, or Dim declaration in a group with one blank line.
  • Keep Option Explicit separated by one blank line before and after, unless a file boundary already supplies it.
  • Separate initialization, input, update, drawing, audio, persistence, and cleanup phases.

Student-first executable structure:

  1. Header comment.
  2. Options and imports.
  3. Constants.
  4. Shared variables and initial state.
  5. Minimum loading/startup preparation.
  6. Game Window near the top.
  7. Startup calls and the primary Do...Loop.
  8. Top-level shutdown and cleanup.
  9. Supporting Sub and Function implementations after the complete main flow.
  10. End Program.

The main loop keeps input, state updates, drawing, Show Screen, and its condition together. Move cohesive reusable helpers into a clearly named local module when that makes the startup story easier to read.

Compact and expanded If blocks:

  • Keep the complete block compact only when every branch has no more than two direct statements, has no nested control block, and contains one logical phase.
  • Expand the complete block when any branch has three or more direct statements, nested control flow, or multiple logical phases.
  • In an expanded block, place one blank line after each branch header and before each following Else If, Else, or End If.
If Key = KEY_ESCAPE Then
    End Program
Else If Key = KEY_ENTER Then
    Call ResetGame()
End If
If Collision = True Then

    Call EndRound()

Else If PlayerX = GoalX And PlayerY = GoalY Then

    Score = Score + 10
    Running = False

    Play Sound "Assets\\Goal.wav"

End If

Long If conditions:

Keep If ... Then on one line only when the rendered line is at most 100 characters and has no more than two top-level Boolean clauses. Otherwise, parenthesize the whole condition, indent each continued clause by four spaces, and leave And or Or at the end of every continued line except the last.

If (Style.CursorWidth < 0 Or
    Style.CursorWidth > UI_MAX_LAYOUT_VALUE Or
    Style.CursorHeight < 0 Or
    Style.CursorHeight > UI_MAX_LAYOUT_VALUE) Then
    Return False
End If

Loops and statement groups:

  • A compact For...End For has no more than four direct statements and no nested control block. Expanded loops place one blank line after For and before End For.
  • Place one blank line before Do, before Loop, and after Loop when a boundary does not already supply it.
  • Treat consecutive Call statements as one visual group with one blank line around the group.
  • Treat consecutive Play Sound statements as one visual group; their spacing overrides compact branch spacing.
  • Follow the last consecutive Unload statement in a group with one blank line.

Multiline declarations and calls:

  • When a routine declaration wraps, keep the opening parenthesis on the declaration line, write one parameter per line, and align the closing parenthesis with the declaration.
  • For a Function, keep As ReturnType on the same line as the closing parenthesis.
  • Use the same shape for multiline calls and preserve argument source order.
  • Write named arguments as Name:=Expression with no spaces around :=.
Public Function CreateActor(
    Name As Text,
    Health As Number,
    Optional Active As Boolean = True
) As Actor

    Dim ReturnValue As Actor

    ReturnValue.Name = Name
    ReturnValue.Health = Health
    ReturnValue.Active = Active

    Return ReturnValue

End Function

Hero = CreateActor(
    Name:="Alyssa",
    Health:=100
)

With, Enum, Type, Class, and Property layout:

  • Leave one blank line after an Enum, Type, or Class header and before its closing line when it contains grouped members.
  • Group fields before methods and properties. In a Class, write Sub New before ordinary methods.
  • Indent Get and Set four spaces under Property, and their bodies four more spaces; place Get before Set.
  • Indent leading-dot members inside With by four spaces and align End With with With.
With WindowStyle
    .BorderThickness = 2

    With .Padding
        .Left = 24
        .Right = 24
    End With
End With

Routine declarations and endings:

Put one blank line after every routine declaration and one blank line before End Sub or End Function. Group routines by responsibility and, when practical, in the order that the main flow introduces them.

Computed function results:

Function IsInsideField(X As Number, Y As Number) As Boolean

    Dim ReturnValue As Boolean

    ReturnValue = X >= 0 And X < FieldWidth And Y >= 0 And Y < FieldHeight

    Return ReturnValue

End Function

Variables, constants, and literals may be returned directly. A computed or evaluated expression must first be assigned to a clearly named local variable so a student can inspect it with Print, hover, or Watch before it is returned.

37W. STUDENT PRACTICE LABS

These labs move from one screen to a reusable two-target game slice. Complete them in order. Each lab has a visible success condition, a code-quality condition, and an extension challenge.

Lab 1 · Beginner

Animated status card

Build: one hero card with a name, level, HP, MP, and ATB bar. Reduce HP with a key and advance ATB in a loop.

Success: labels never overlap, values remain centered, and every gauge clamps between zero and its maximum.

Stretch: flash the card border for six frames when damage occurs.

Lab 2 · Beginner 3D

Orbiting arena viewer

Build: a plane, a repeated grid, three primitives, and a camera using UpdateCameraControlsFromPointer.

Success: primary drag pans, the wheel zooms while panning, middle drag completes a full orbit, and release returns gently to the authored camera.

Stretch: exclude clicks that begin on a projected actor.

Lab 3 · Intermediate

Two-wave encounter

Build: two lesser enemies in wave one and one boss in wave two. Keep defeated bodies until the next wave starts, then clear them.

Success: HUD rows are left-aligned and equal width, camera framing uses active bounds, and the boss is not created by Dragonfall-specific library code.

Stretch: add a deterministic fly-in or teleport entrance without pausing input processing.

Lab 4 · Intermediate

Automatic and manual ATB

Build: let AI choose actions until the player toggles manual mode. Highlight the ready hero and offer Attack, Skill, Defend, and Item.

Success: both modes submit through BattleTime.SubmitAction; returning to automatic mode does not restart or lose queued state.

Stretch: implement Active and Wait time modes and explain the difference to a classmate.

Lab 5 · Advanced presentation

Readable contact and spell language

Build: a physical impact, a fire spell, an ice spell, and a healing aura using data-driven presets.

Success: hits flash and display damage, misses display no contact effect, healing uses a distinct upward aura, and every effect is synchronized with sound and camera framing.

Stretch: add a rare boss special that pushes the party back and applies a temporary burning presentation state.

Lab 6 · Capstone

Ship Windows first, Web second

Build: compile the same project for Windows 64-bit and Web, then keep a short platform test log.

Success: Windows meets the visual target and minimum FPS with native MSAA; Web passes real input, resize, rendering, and audio testing. Both targets preserve identical simulation results for a fixed seed.

Stretch: add a quality setting only if Web measurements justify it, leaving native quality as the default high bar.
