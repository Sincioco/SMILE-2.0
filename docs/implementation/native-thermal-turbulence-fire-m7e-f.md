## Implementation

`thermal_fire3d.h` supplies deterministic reference dynamics and matching native HLSL expressions. Existing 80-byte GPU state remains intact. Per-system thermal settings use eight float4 values; the complete GPU update constants occupy 144 bytes.

Command 127 suboperations 11–15 configure forces, turbulence, evolution, bounds and render policy. Query 22 identifies native thermal support; queries 51–59 expose CPU/reference diagnostics. GPU visual state is not read back or presented as CPU-observed data.

Dynamics include gravity, wind, buoyancy, exponential delta-time-aware drag, seeded one-/two-octave analytic turbulence, cooling, density dissipation, size growth, speed clamp, invalid-state rejection and world-bound termination. Noise time wraps after 4096 seconds. Medium selects one octave; High selects two.

Thermal presentation includes a hot core, yellow/gold inner flame, orange/red outer tongues, alpha smoke, additive small randomized embers, soft depth, localized heat distortion, HDR bloom and direct LDR. Smoke emission, density and opacity were reduced following Sin's review. Original deterministic assets are generated by `scripts/generate-thermal-fire-assets.ps1`; their provenance and SHA-256 values are in `TechnicalAssets/Generation3/Fire/README.md`. The gradient image is an inspectable reference; equivalent thermal colors are evaluated analytically in the shader.

### High-level API

`Smile.Simple3D.FireEmitter3D` provides bounded point, cone and segment emitters; one-shot presets; deterministic CPU scheduling; GPU visual motion; complete CPU fallback; generation/epoch-safe handles; atomic admission and teardown. Settings and destruction are rejected inside an active frame. Source motion is inherited within limits; teleports break inherited velocity. Accepted submissions retain their material/texture state.

Lifecycle: `Initialize`, `StartAt`/`StartOnSegment`, `SetSegment`/`SetPosition`, `Update`, `Draw`, `StopEmitter`, `Destroy`, `Shutdown`. See the library API for exact signatures and diagnostic query meanings.

Initial presets: TorchFire, BrazierFire, LineFire, PaladinBladeFire, Fireball, FireBurstGen3, DragonFireBreathPreview. The production Arin slash/trail work belongs to M7E-G, not this checkpoint.

FireBurstGen3 preserves the user-approved expanding hot charge followed by a rapid explosion. Its charge has both vertical and horizontal wisps. The technical dragon-breath preview has a mouth-source charge and rapidly traveling fireball; it is not a newly animated dragon or gameplay damage system.

### Grid anti-aliasing with heat

Heat no longer forces the native scene to single-sample. HDR and direct LDR retain supported 4x/2x/1x MSAA. The renderer resolves the opaque scene for distortion, composites to scratch, copies color back without tone mapping, preserves the MSAA depth surface for transparent draws, then performs the normal final resolve/post-processing. The RTX 5090 lab reports four scene samples with heat enabled. This is shared renderer behavior and also applies when fire is later added to Arin.

## Resources and performance

- Four logical emitters; eight shared native GPU systems; global 32768 GPU slots, maximum 16384 per system.
- High: five systems, 1664 slots (512 core, 512 outer, 256 smoke, 128 embers, 256 heat), 266960 state bytes. Medium halves these budgets. CPU Low uses four 96-slot batches and omits thermal/heat parity.
- A second five-layer High emitter cannot fit the eight-system pool; it falls back atomically to CPU Low. No claim of four simultaneous full-High torches is made.
- Shared fire initialization owns three textures and five materials. Lifecycle tests verify rollback, repeat initialization, exact teardown and renderer-epoch invalidation.
- The bounded native performance fixture covers 32 combinations: one 1024-slot system, four 1024-slot systems, one 4096-slot system and one 16384-slot system, crossed with HDR, soft depth and heat on/off. Heat adds 64 fixture slots where enabled.
- Window request: 1920×1080. Actual target: 1920×1061. Results are CPU submission plus presentation timing, not GPU timing; GPU timers are explicitly unavailable. The exact measured scenario lines are in `screenshots/m7e-f-native-thermal-fire/native-validation.txt`.
- Warm simulation uploads are zero after fixture initialization. There is no GPU-particle readback. The fixture exercises renderer device-loss/recreate callbacks; it does not physically reset the Windows display driver.
